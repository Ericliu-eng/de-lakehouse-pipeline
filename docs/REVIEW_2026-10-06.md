## 优先处理的问题

P1：可能污染数据、影响持续加载或造成数据丢失；P2：功能缺陷、可靠性问题；P3：维护与证据问题。标注“静态”的项由代码路径推导，本次未在真实 PostgreSQL 中复现。

### F01 · P2 · 当前 benchmark 已无法运行（已复现）

位置：`scripts/benchmark.py:173`、`src/de_lakehouse_pipeline/pipeline.py:76`。

`replay()` 的 `save_to_temp(data, name, root=None, run_date=None)` 不接受 `symbol`，而主流程现在传入 `symbol=symbol`。首轮加载立即抛出 `TypeError: ... unexpected keyword argument 'symbol'`。历史 benchmark 结果不因此失效，但当前代码不能重现它们。

建议：替代函数显式接收并转发 symbol；补一项执行真实 replay 上下文和真实 pipeline 调用的离线契约测试，避免仅测试独立组件。

### F02 · P1 · 未来日期会把增量水位推进到未来（部分复现＋静态）

位置：`transform/staging/staging_market_bars.py:33`、`:75`，`pipeline.py:138`，`quality/checks.py:189`。

staging 接受 `2099-01-01`；加载后将最大日期写入 watermark。freshness 只判断 `age_days <= 14`，负数也通过。一次未来日期数据就可能使之后所有正常日期都被 `ts > watermark` 排除。事务原子性不能解决这种业务错误。

建议：写入前验证交易日期不晚于允许的市场日期，freshness 同时检查下界；提供修正坏行及重建 watermark 的恢复步骤。补未来时间、市场时区及恢复后的增量测试。

### F03 · P1 · 数值验证不足，非法数值可穿过质量门禁（部分复现＋静态）

位置：`quality/schema_validation.py:12`，`transform/staging/staging_market_bars.py:61`、`:102`，`quality/checks.py:204`，`migrations/003_market_bars.sql`。

validator 只验证字段存在且非 null。`float('nan')`、`float('inf')` 可成功转换；Tiingo 的 `int(1.9)` 静默变成 1。负 open/high/low、high < low、close 超出 high/low 都未校验。生产门禁只检查 close 和 volume 的下界，不能完整验证 OHLCV；数据库价格列也允许 NULL。异常数值还可能导致 API JSON 序列化失败。

建议：统一验证有限数值、非负价格、整型成交量、OHLC 一致性和业务 null 约束；不要把成功类型转换等同于合法数据。必要的数据库约束通过新增迁移加入。测试应覆盖两种数据源的同一组边界输入。

### F04 · P1 · 手动 marts 路径绕过质量检查（静态）

位置：`src/de_lakehouse_pipeline/cli.py:23`，`docs/RUNBOOK.md`、README 中 Tiingo 后的 `make run-marts`。

CLI `run_marts()` 直接构建三张表。Tiingo 路径也没有调用 SQL 质量门禁。因此“回填 → run-marts”或“run → run-marts”可以发布编排本来会拒绝的负价格等数据。SVG 已说明这是 bypass，但 README 对“仅检查通过才重建”的总体表述仍过强。

建议：建立所有发布入口共用的验证与构建函数；历史回填的 freshness 使用合适范围，不直接套用当前日期。若保留绕过模式，应明确命名并显式选择。补手动入口遇到坏数据时 marts 不变化的测试。

### F05 · P1 · 同一股票并发运行可能回退水位和覆盖新数据（静态）

位置：`pipeline.py:115`，`load/db/pipeline_metadata.py:37`，`load/db/stock_writer.py`。

两个任务可读取相同旧水位，分别处理较新和较旧响应；较旧任务后提交时会把 watermark 无条件写回较小值，也可能用旧快照覆盖重叠行情。单次事务只保证该次原子性，不保证多个运行之间的顺序。历史回填在 Python 中做 max 也有同样竞争窗口。

建议：对相同 source/symbol 串行化（包括首次插入时的协调），数据库使用单调水位更新，并定义行情版本优先级。不要只加 GREATEST 后就认为旧值覆盖问题也解决了。补双连接交错提交测试。

### F06 · P1 · 原始文件共享路径使并发任务读到另一份响应（静态）

位置：`ingest/io.py:31`，`pipeline.py:76`、`:92`。

同一天同一 symbol 固定写 `stock.json`，使用截断写入且随后重新从该路径加载。A 保存后、读取前，B 可以覆盖文件；A 随后处理 B 的数据。更坏的交错会读到半截 JSON。即使不开并发，同日失败重跑也覆盖本地证据。S3 版本控制不能保护本地重新读取这一步。

建议：raw 路径包含 run_id，临时文件完成后原子替换，并让该次运行只读取自身不可变文件。记录 checksum 和 raw URI；S3 如保留固定 key，应记录 VersionId。

### F07 · P2 · 当前 backfill 无法修正已存在的历史价格（静态；文档已部分承认）

位置：`backfill.py:60`、`:80`，`docs/INCREMENTAL.md` 的历史纠错说明。

数据库已有的 alpha_vantage 日期会被当作完成而跳过；普通增量又忽略水位之前的数据。因此供应商修正旧价格后，文档推荐的 backfill 命令并不会更新它，删除本地 checkpoint 也无效。`run_stock_for_date` 本身能 upsert，但范围入口不会调用它处理已有日期。

建议：增加明确的 force/reprocess 模式，并保留默认的缺口补齐语义；返回实际更新、缺失和跳过日期。Tiingo insert-only 是明确设计，不应直接改为无条件覆盖。

### F08 · P2 · marts 的“重建”不会清除源表已删除的记录（静态）

位置：`sql/marts/mart_daily_symbol_summary.sql`、`mart_symbol_latest_price.sql`、`mart_symbol_volume_rank.sql`。

三份 SQL 都只 INSERT/UPDATE。删除坏行情后再构建，已无源记录的 daily summary 仍存在，volume rank 又继续基于它排名；删除一个 symbol 全部数据后，latest price 仍能被服务。修复源表不能保证修复下游。

建议：全量模式在同一事务内替换完整结果，或明确同步删除受影响分区；加入“先构建、删除源行、再构建”的测试。

### F09 · P2 · DSN 手工拼接不能处理合法复杂密码（已复现）

位置：`load/db/connection.py:34`。

password、user、dbname 直接拼接进 libpq DSN，没有正确转义。假密码 `example password` 已使 conninfo 解析抛出 ProgrammingError；不需要真正连接数据库就能复现。

建议：向 psycopg.connect 传关键字参数，或使用 psycopg 的 conninfo 构造工具。补空格、引号、反斜线案例；DBConfig.password 不应出现在默认 repr 中。

### F10 · P2 · 宣称支持 Python 3.10，但测试使用 3.11 才有的 datetime.UTC（静态）

位置：`tests/unit/test_run_repository.py:1`、`tests/integration/test_observability_repository.py:1`，`pyproject.toml`、README、CI。

在 Python 3.10 上测试收集即会因该 import 失败。CI 没有 setup-python 和版本矩阵，依赖 ubuntu runner 默认版本，无法验证声明的最低版本。

建议：改成 timezone.utc 并实际测试最低支持版本，或统一提高最低版本；运行依赖也需验证同一兼容范围。

### F11 · P2 · 两个 smoke 测试被默认 make test/CI 漏掉（静态）

位置：`tests/smoke/test_cloud_storage_smoke.py:14`、`test_metrics_sla_smoke.py:4`，Makefile 的 smoke/smoke-db。

这两个文件没有 smoke marker。`make test` 通过 `-m smoke` 分两次筛选 smoke 目录，因此两项均不执行；`make test-all` 才覆盖。这也解释了历史 157 与 159 的差异，不能把它们描述成完全相同的完整套件。

建议：统一目录级 marker 或让目录成为唯一筛选依据，并以 pytest 收集结果检查默认测试集合和全量集合的差异。

### F12 · P2 · load audit 时间被写成当天零点（静态）

位置：`load/metadata.py:10`、`load/db/metadata_writer.py`、`migrations/004_load_metadata.sql`。

`recorded_at` 传入 date.today().isoformat()，覆盖数据库 NOW() 默认值。一天内多个加载全部落在零点，且解释受数据库时区影响，无法正确排查运行顺序和真实写入时间。

建议：使用 UTC datetime 或省略该列使用数据库默认值；另行增加 symbol、run_id、raw URI，不用 version=日期替代运行标识。

### F13 · P1 · benchmark 会强制删除已经存在的同名数据库（静态，未执行）

位置：`scripts/benchmark.py:111`、`:117`。

只检查目标不等于当前 DB_NAME，然后执行 DROP DATABASE ... WITH (FORCE)。指定另一个已有业务库，或默认 lakehouse_benchmark 恰好已存放有用数据时，会断开连接并删库。名称不同不代表可丢弃。

建议：生成唯一数据库名，只清理由本次创建的数据库；发现目标已存在应拒绝，而不是重建。用 fake admin connection 验证拒绝逻辑即可，无需用真实数据实验。

### F14 · P2 · benchmark 可能向真实 PipeGuard 发送模拟结果（静态）

位置：`scripts/benchmark.py:800`、编排调用处，`tests/conftest.py`。

脚本关闭 S3，但没有关闭 PIPEGUARD 配置。导入行情模块会加载 .env；基准质量故障注入和多次 replay 随后调用真实 orchestrator，可能把假失败、假运行量上报到用户监控。tests 的自动 fixture 不适用于独立脚本。

建议：benchmark 显式禁用全部外部副作用（最好注入 reporter），并测试即使环境变量存在也不发送网络请求。

### F15 · P2 · 交易日期依赖数据库会话时区（静态）

位置：`sql/marts/mart_daily_symbol_summary.sql:12`，`load/db/stock_reader.py`，`scripts/price_dashboard.py`。

`ts::date` / DATE(ts) 使用会话时区。行情按美东午夜保存，在美国西海岸会话中会变成前一天，影响聚合日期和回填完成判断。当前默认 UTC 对美股样本通常恰好没问题，但配置没有强制该条件。

建议：显式使用市场时区提取 trading_date，或直接存独立的交易日 DATE；用 UTC、纽约、洛杉矶和夏令时测试同一天结果一致。

### F16 · P2 · symbol 校验缺乏路径约束，表之间长度约束也不一致（部分复现＋静态）

位置：`symbols.py`、`ingest/io.py`、`migrations/005_marts.sql`。

normalize_symbol('../../AUDIT') 原样接受路径分隔符。Tiingo 的显式 symbol 和 raw 保存函数直接参与路径拼接，可能写出预期 symbol 分区。与此同时，fact symbol 是 TEXT，daily summary 是 VARCHAR(10)，长 symbol 能进 fact 却让 marts 失败。

建议：定义明确的 symbol 契约，允许真实业务需要的点、横线等字符，拒绝路径组件和控制字符；解析后确认路径在 raw root 下；统一各表限制。不要把这描述为现有远程 API 漏洞：当前入口主要是本地 CLI/函数。

### F17 · P2 · “每个错误均脱敏”的承诺不成立（已用假密钥复现）

位置：`ingest/market_data_client.py:79`、`README.md`、`docs/SECRETS_AND_COST.md`。

HTTPError、ConnectionError 和 RuntimeError 路径做了脱敏，但 Error Message 直接 ValueError。若上游错误文本回显凭据，它会进入 pipeline 的异常日志，之后可能进入运行记录和报告。已用模拟响应证明原样输出假密钥；未证明真实供应商当前会回显。

建议：对所有离开客户端的错误统一清洗，包括不同编码形式；补 provider error envelope 测试。不要记录真实凭据来测试。

### F18 · P2 · 空结果 CSV 缺少业务字段（已复现）

位置：`export/market_bars.py:57`。

DataFrame([]) 没有列，rename 不会创建 event_ts，最终文件仅含 `snapshot_id,ingested_at`。无数据股票导出的 schema 与有数据时不同，依赖固定表头的消费者会失败。
